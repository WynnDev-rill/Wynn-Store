Architecture: Compose settings → local preferences/model store → user-started `specialUse` foreground service → bounded translucent GLSurfaceView → Cubism Java Framework/JNI with a bounded ES2 ArtMesh/clipping adapter. The official R5 renderer integration produced zero visible pixels for both the MIT model and official SDK sample on the Android 16 emulator, so rendering was isolated behind a smaller standard-mesh adapter while retaining SDK rig, physics, expressions and motions. A pure Kotlin state engine drives timing and movement; the model renderer drives existing rig parameters and files. No native walking cycle is invented when a rig lacks one.

## 1.1.0 behavior review

Studied primary sources [Shimeji-ee actions](https://github.com/TigerHix/shimeji-ee/blob/master/conf/actions.xml) and [VPet animation architecture](https://github.com/LorisYounger/VPet/blob/main/Secondary%20Development%20Support%20Documentation.md). Shimeji separates random destinations/behavior sequences from pose-specific walk/run/sit assets; VPet separates interaction and animation start/loop/end. Their sprite/WPF runtime and character artwork are not Cubism animations. No source or artwork was copied; reused the existing Cubism motion/expression pipeline instead, with a model-owned locomotion selector, phased hops, drag feedback and touch gaze. Existing Akimeji/WhaleGirl findings remain above.

Owner-provided Furina ZIP inspected locally (not committed or bundled): one wave motion, wave/anger/heart/blush expressions; CDI metadata exposes head/body/eye/cloth/hair controls but no clearly labeled independent walking-leg parameters. No walking or sitting cycle was found. A single leg part is not an articulated walking rig. This build does not claim natural Furina footfalls or sitting. The original model data stays private. Procedural leg sway touches only explicit recognized IDs; unknown parameters are not guessed.

Updater reuses the ScreenGuard pattern of a guarded check, bounded network response, clear progress/result and an automatic availability dialog. The actual implementation is small and independent; ScreenGuard's Shizuku/usage infrastructure is not included. No public APK channel is fabricated or published: the existing license/publication gate still applies.


## 1.2.0 asset-first update

- Reused the owner-provided ZIP unchanged for the private initial model (one original wave motion, four original expressions, MOC3 rig, two textures, CDI labels, physics). Public git/CI does not contain or retrieve these bytes. Personal APK packaging is separately enabled with `FP_PERSONAL_MODEL=true`. No public release is published.
- Studied [Daidai Live2D Pet](https://github.com/Rosa134/daidai-live2d-pet) and its MIT license: model-owned random motions and contextual bubbles fit, but Electron/PixiJS/TTS/server code would replace the native renderer and add unnecessary cost. No code/art was copied. The P1r2y/L2dvpet source lookup returned 404, so its search excerpt was not used as implementation authority.
- Reused the existing official Cubism Java rig/motion/physics renderer and Android WindowManager/TextView/property animator. Shimeji/VPet sprite pose cycles are incompatible with this MOC3 rig. Searches did not yield an animator-authored walk cycle compatible with the exact Furina parameters; transplanting another rig's motion was rejected. Therefore only the small missing gait adapter, event detector and localized dialogue were implemented here.
- Official [Cubism Core API](https://docs.live2d.com/en/cubism-sdk-manual/cubism-core-api-reference/) supports retrieving drawable vertex positions and parent parts. Inspection with unmodified official Web Core 5.1.0 (private QA only) found four leg drawables grouped under the CDI-labelled leg part, two per side including shoes. Their own textures and geometry were reused. No Core binary or original MOC3 data was modified. The optional render-buffer offsets hold hip vertices fixed and lift alternate feet; run mode increases stride/lift. This remains a front-facing chibi shuffle, not a rebuilt side-view walking/sitting rig.
- [Android overlay window documentation](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_NOT_TOUCHABLE) informed the separate small non-touchable bubble with opacity 0.8. Bubble timing is local, no accessibility/usage access/screenshot permission or AI endpoint was added. The user explicitly deferred AI.

## 1.3.0 asset decisions

- Inspected the exact owner ZIP again: original wave, anger/heart/blush expressions, standard eye/brow/head/body controls, `ParamMouthOpenY`, and an **empty** LipSync ID list. Therefore the renderer resolves an existing standard mouth parameter when the list is empty. No authored sit/swing/read/eat motion was found. No compatible downloadable pose set for this exact rig was established; other Furina Live2D models and VPet sprite packs cannot safely supply its missing pose curves.
- Reused Twemoji 14.0.2 [open book](https://github.com/twitter/twemoji/blob/v14.0.2/assets/svg/1f4d6.svg) and [shortcake](https://github.com/twitter/twemoji/blob/v14.0.2/assets/svg/1f370.svg), graphics CC BY 4.0, © Twitter, Inc. and contributors. The upstream 72×72 PNGs are bundled as small GL prop textures; native transforms animate page turning, a fork, bite progression and fades. Full license: `docs/licenses/TWEMOJI-CC-BY-4.0.txt`. Fork/page/sparkle primitives are app-owned. Rejected a new raster drawing/AI-generated character pose because it would replace identity rather than reuse the rig.
- Read/cake are explicitly native vignettes with existing facial rig controls and props, not newly authored arm/leg animation. Sitting/swing buttons remain unavailable unless the selected model has a matching motion or an owner-selected mapping. No squashed-leg or static-standing-as-sitting approximation was introduced.
- Owner-only Japanese audio is sourced from the [Furina Japanese voice-over catalog](https://genshin-impact.fandom.com/wiki/Furina/Voice-Overs/Japanese) and its public media CDN: Opening Treasure Chest 01 (cake/surprise, 4.312 s), 03 (pet response, 3.060 s); Light Hit Taken 01/02 (poke, 0.400/0.458 s); Sprint Start 01 and Light Attack 01 (hop, 0.214/0.308 s). Original performance/game audio remains owned by the respective rights holders; wiki availability is not a redistribution license. No synthetic impersonation was created. The original files, source URLs, SHA-256 and envelopes stay in ignored `.deps/personal-assets/personal/voice/manifest.json`, included only in the owner's personal APK and never fetched in public CI. Public publication stays gated.
- Envelope generation: decode original audio with FFmpeg to mono PCM16/16 kHz, 20 ms RMS bins, noise floor 0.012, gain 3.5, clamp 0..1. Runtime uses Android MediaPlayer time and attack/release smoothing in the existing model update. No AudioRecord, Visualizer, RECORD_AUDIO or external TTS dependency.


## 1.4.0 seated body and held-object decisions — 27 October 2026

Rechecked the five-product benchmark before implementation. VPet/Shimeji sequences remain useful for activity timing but none supplies compatible motion curves for the exact owner MOC. Also inspected [cartoonation's Furina Shimeji](https://cartoonation.tumblr.com/) (creator download and repost/credit restrictions) and [Ice-teapop/desktop-pet](https://github.com/Ice-teapop/desktop-pet) (MIT SVG sprites). Both use another character drawing/sprite runtime; neither preserves this supplied Live2D identity, so no artwork/code was copied.

Private original-mesh inspection found independent normal arms, legs and shoes. The app therefore reuses their existing textures/meshes through a bounded app-owned two-bone arm adapter and frontal thigh/shin projection. The exact MOC3 digest gates support, with no proprietary data embedded in the source. No Core or MOC files are edited. [Official Cubism mesh API](https://docs.live2d.com/en/cubism-sdk-manual/cubism-core-api-reference/), [Spine IK concepts](https://us.esotericsoftware.com/spine-ik-constraints) and [mesh weights](https://us.esotericsoftware.com/spine-weights) informed the mathematical approach; no Spine software/runtime/source is included.

No reusable furniture asset was compatible with the model anchors and blue/gold palette. Small chair/swing geometric art is generated once with Android Canvas in `StageFurniture.kt`. Book/cake reuse the already credited Twemoji textures; hand-aligned fork/page primitives remain app-owned. The original owner ZIP and all six Japanese audio files/envelopes are preserved byte-for-byte. These native frontal poses do not create a new 3D viewpoint or transplant another model's authored curves.
